📖 第一章：什么是消息队列？为什么要用它？

▼

🤔 先思考一个问题

想象你在一家餐厅点餐：

❌ 没有消息队列的情况

服务员亲自去厨房盯着厨师做菜 → 等厨师做完 → 服务员端给你

问题在哪？

  • 服务员要一直等着，不能做其他事
  • 如果客人很多，服务员忙不过来
  • 如果厨师做菜很慢，所有人都在等

✅ 有消息队列的情况

把订单交给前台收银 → 收银员转身继续接待下一位客人 → 厨房收到订单排队做菜 → 菜做好了通知你来取

这样前台可以同时接待很多人，厨房有条不紊地工作。

💡 什么是消息队列？

📦 消息队列（Message Queue）

就像餐厅的前台收银系统：你把"订单"（消息）交给队列，队列会按顺序保存，厨师（消费者）可以从队列中取出订单来处理。

核心特点：

  • 🔗 解耦：发送者和接收者不需要知道对方的存在
  • ⚡ 异步：发送消息后可以立即返回，不用等待处理完成
  • 📊 削峰填谷：高峰期积累的请求会慢慢被处理，不会系统崩溃
  • 💪 可靠性：消息会持久保存，不会丢失

🏢 什么时候需要消息队列？

📧 场景1：用户注册后发送欢迎邮件

🤔 没有队列

用户注册 → 系统注册 → 发送邮件 → 返回成功
如果邮件服务器慢，用户要等很久

✅ 有队列

用户注册 → 系统注册 → 发到队列 → 立即返回"注册成功"
后台发送邮件（用户无感知等待）

📷 场景2：处理大量图片上传

没有队列：用户上传100张图片 → 系统一张张处理 → 用户等待5分钟

有队列：图片进入队列 → 立即返回"上传成功" → 5个后台worker同时处理 → 1分钟完成

📊 消息队列 vs 直接调用

对比项直接调用消息队列
耦合度高（紧密耦合）低（通过队列通信）
性能同步等待异步处理
可靠性失败即失败可以重试
扩展性难扩展容易增加消费者

🏗️ 第二章：RabbitMQ核心概念详解

▼

🐇 RabbitMQ 是什么？

RabbitMQ 是一个实现了 AMQP（高级消息队列协议）的消息中间件。简单理解：它是帮你管理"消息队列"的软件。

同类产品还有：Kafka、Redis 队列、ActiveMQ 等

📐 核心架构图

flowchart LR P["📤 Producer"] -->|"publish"| EX["🔀 Exchange"] EX -->|"route"| Q["📭 Queue"] Q -->|"consume"| C["📥 Consumer"] style P fill:#61DAFB style EX fill:#FF6B6B style Q fill:#98FB98 style C fill:#FFD93D

🍽️ 用餐厅来理解

  • 生产者(Producer) = 顾客（点餐的人）
  • 交换机(Exchange) = 前台收银员（决定订单去哪）
  • 队列(Queue) = 厨房的排队单子（按顺序等待处理）
  • 消费者(Consumer) = 厨师（处理订单的人）

📦 详细解释每个概念

1. 生产者 (Producer)

生产者是发送消息的程序/代码。工作流程：创建消息 → 把消息发送到 RabbitMQ → 发送完成后继续做其他事（异步）

2. 消费者 (Consumer)

消费者是接收和处理消息的程序/代码。工作流程：从队列取消息 → 处理消息 → 告诉 RabbitMQ "处理完了"（确认）

3. 队列 (Queue)

队列是存储消息的容器。特点：先进先出（FIFO）、可持久化、可设置过期时间、可设置队列长度限制

4. 交换机 (Exchange)

交换机是消息的分配中心，决定消息应该去哪个队列。

5. 绑定 (Binding) + 路由键 (Routing Key)

绑定是连接交换机和队列的规则。路由键是消息的标签，交换机根据它决定消息去哪。

🎯 四种交换机类型

类型说明比喻

fanout广播到所有队列广播通知，所有人同时收到

📥 消费者：接收消息

consumer.py
import pika

connection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
channel = connection.channel()
channel.queue_declare(queue='hello', durable=True)

def callback(ch, method, properties, body):
    print(f"📥 收到消息: {body.decode()}")
    ch.basic_ack(delivery_tag=method.delivery_tag)

channel.basic_consume(queue='hello', on_message_callback=callback)
print("📡 正在等待消息... 按 Ctrl+C 退出")
channel.start_consuming()

📋 消息确认机制

为什么要"确认"？如果消费者收到消息处理到一半崩溃了：

🔧 发送任务消息

send_tasks.py
import pika
import json

connection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
channel = connection.channel()
channel.queue_declare(queue='task_queue', durable=True)

tasks = [
    {"task_id": 1, "type": "发送邮件", "data": "user@example.com"},
    {"task_id": 2, "type": "生成报表", "data": "2024-01"},
    {"task_id": 3, "type": "压缩图片", "data": "photo.jpg"},
]

for task in tasks:
    channel.basic_publish(
        exchange='', routing_key='task_queue',
        body=json.dumps(task).encode(),
        properties=pika.BasicProperties(delivery_mode=2)
    )
    print(f"📤 已发送任务: {task['task_id']}")

connection.close()

👷 启动多个工人

worker.py
import pika
import json
import time
import random

def worker(worker_name):
    connection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
    channel = connection.channel()
    channel.queue_declare(queue='task_queue', durable=True)
    channel.basic_qos(prefetch_count=1)  # 关键：公平分发

    def callback(ch, method, properties, body):
        task = json.loads(body.decode())
        print(f"👷 {worker_name} 收到任务: {task['task_id']}")
        time.sleep(random.randint(1, 3))  # 模拟处理
        print(f"✅ {worker_name} 完成任务")
        ch.basic_ack(delivery_tag=method.delivery_tag)

    channel.basic_consume(queue='task_queue', on_message_callback=callback)
    channel.start_consuming()

if __name__ == '__main__':
    worker("工人A")

2️⃣ direct 交换机（精确匹配）

根据日志级别发送到不同的队列。

flowchart TB EX["📝 direct 交换机
日志系统"] -->|"info"| Q1["ℹ️ info_queue"] EX -->|"warning"| Q2["⚠️ warning_queue"] EX -->|"error"| Q3["🚨 error_queue"] style EX fill:#FF6B6B
direct_publisher.py
import pika

connection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
channel = connection.channel()
channel.exchange_declare(exchange='logs', exchange_type='direct')

queues = {'info_queue': 'info', 'warning_queue': 'warning', 'error_queue': 'error'}
for queue, routing_key in queues.items():
    channel.queue_declare(queue=queue, durable=True)
    channel.queue_bind(exchange='logs', queue=queue, routing_key=routing_key)

logs = [
    ('info', '用户张三登录了系统'),
    ('warning', '磁盘空间不足80%'),
    ('error', '数据库连接失败'),
]

for level, message in logs:
    channel.basic_publish(exchange='logs', routing_key=level, body=message.encode())
    print(f"📝 [{level.upper()}] {message}")

connection.close()

📥 接收者代码

topic_consumer.py
import pika

def logistics_consumer(queue_name, binding_key):
    connection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
    channel = connection.channel()
    channel.exchange_declare(exchange='logistics', exchange_type='topic')
    channel.queue_declare(queue=queue_name, durable=True)
    channel.queue_bind(exchange='logistics', queue=queue_name, routing_key=binding_key)

    def callback(ch, method, properties, body):
        print(f"📥 {queue_name} 收到: {body.decode()}")
        ch.basic_ack(delivery_tag=method.delivery_tag)

    channel.basic_consume(queue=queue_name, on_message_callback=callback)
    print(f"👂 {queue_name} 监听: {binding_key}")
    channel.start_consuming()

# 示例：监听所有电子产品
logistics_consumer('electronics_queue', '*.electronics.*')

📤 订单服务（生产者）

order_publisher.py
import pika
import json
import time

class OrderPublisher:
    def __init__(self):
        self.connection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
        self.channel = self.connection.channel()
        self.channel.exchange_declare(exchange='orders', exchange_type='topic')

        bindings = [
            ('inventory_queue', 'order.created'),
            ('payment_queue', 'payment.process'),
            ('notification_queue', 'order.*'),
            ('analytics_queue', '#')
        ]
        for queue, routing_key in bindings:
            self.channel.queue_declare(queue=queue, durable=True)
            self.channel.queue_bind(exchange='orders', queue=queue, routing_key=routing_key)

    def create_order(self, order_id, user_id, items, total_amount):
        order = {'order_id': order_id, 'user_id': user_id, 'items': items, 'total_amount': total_amount, 'timestamp': time.strftime('%Y-%m-%d %H:%M:%S')}
        self.publish('order.created', order)
        self.publish('payment.process', {'order_id': order_id, 'amount': total_amount})
        return order

    def publish(self, routing_key, message):
        self.channel.basic_publish(exchange='orders', routing_key=routing_key,
            body=json.dumps(message).encode(), properties=pika.BasicProperties(delivery_mode=2))
        print(f"📤 发送: [{routing_key}] {message}")

    def close(self):
        self.connection.close()

if __name__ == '__main__':
    publisher = OrderPublisher()
    order = publisher.create_order('ORD001', 'USER001', [{'name': 'iPhone 15', 'price': 7999}], 7999)
    publisher.close()

👷 消费者服务

inventory_service.py
import pika
import json

def inventory_service():
    connection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
    channel = connection.channel()
    channel.queue_declare(queue='inventory_queue', durable=True)
    channel.queue_bind(exchange='orders', queue='inventory_queue', routing_key='order.created')

    def callback(ch, method, properties, body):
        order = json.loads(body.decode())
        print(f"📦 库存服务收到订单: {order['order_id']}")
        for item in order['items']:
            print(f"   检查 {item['name']} 库存: 充足")
        print(f"✅ 库存检查通过")
        ch.basic_ack(delivery_tag=method.delivery_tag)

    channel.basic_consume(queue='inventory_queue', on_message_callback=callback)
    channel.start_consuming()

✅ 最佳实践

1. 连接管理

# ❌ 不推荐：每次发送都创建连接
def send_message(message):
    connection = pika.BlockingConnection(...)
    channel.basic_publish(...)
    connection.close()

# ✅ 推荐：复用连接
connection = pika.BlockingConnection(...)
channel = connection.channel()
def send_message(message):
    channel.basic_publish(...)  # 复用连接

2. 消息持久化

channel.queue_declare(queue='my_queue', durable=True)  # 队列持久化
channel.basic_publish(..., properties=pika.BasicProperties(delivery_mode=2))  # 消息持久化

3. 消费者确认

channel.basic_consume(queue='my_queue', auto_ack=False)  # 手动确认

def callback(ch, method, properties, body):
    try:
        process(body)
        ch.basic_ack(delivery_tag=method.delivery_tag)
    except Exception:
        ch.basic_nack(delivery_tag=method.delivery_tag, requeue=True)

4. 公平分发

channel.basic_qos(prefetch_count=1)  # 同一时间只处理1条消息

❓ 常见问题

Q1: 消息丢失怎么办？+

原因：队列或消息没有持久化

解决：队列持久化 + 消息持久化 + 手动确认

Q2: 消费者处理失败怎么办？+

使用重试机制：ch.basic_nack(delivery_tag=method.delivery_tag, requeue=True)

Q3: 如何监控队列？+

管理界面：http://localhost:15672（用户名/密码：guest/guest）

可以查看：队列状态、交换机绑定、连接状态、消息吞吐量
